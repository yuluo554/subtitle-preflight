# 技术报告 · 字幕投放前体检（subtitle-preflight）

> 口径唯一真相源：`data/README.md` §4。本文**不重复数值**，只引用口径键。
> 本报告的所有数字都是**本机实测**（2026-10-19，Node `v24.15.0`，Windows + Git Bash）。
> 远端未建：凡涉及 CI 的表述一律写成"本地等价校验（未接远端，CI 待首推验证）"。

---

## 一、这是什么

把 `.srt` / `.vtt` / `.ass` 拖进**一个 HTML 文件**，浏览器内解析，按「时序 / 阅读速度 / 行长 /
排版卫生」四类确定性规则体检，输出带**源文件行号定位**的 JSON / Markdown / CSV 报告，
以及**只做可逆修复**的字幕文件。

- 形态唯一：单文件 HTML，双击即用；零安装、零上传、零外网请求、断网可用。
- 运行时**零第三方依赖**；`node_modules/` 不入仓。
- 不引入 WASM、不调用模型、不做分词：全部规则都是字符串与时间戳运算。

## 二、为什么值得做（依据）

需求原话与检索快照见 `data/README.md` §1（D1–D9 九条原话，逐条带出处）。摘录两条最直接的：

- **D1**："this only works with offsets and doesn't adjust the subtitle's playback speed…
  usually caused by playing a subtitle written for a given FPS played back on a different FPS"
  ——帧率不匹配导致的**等比漂移**不是"整体偏移"能修的，需要拟合 `scale`。
- **D5**："细看下来其实译文的意思也没有错…可能只是因为**字幕断句断的不好**"
  ——断句问题属于翻译/润色工具，本项目**明确不做**（见 §六 非目标）。

头部在位者是 `SubtitleEdit`（14603★，C# 桌面程序）与若干 0–3★ 一次性脚本；
「单文件 HTML + 三格式统一 + 中文阈值 + 行号定位 + 可逆修复」这一格未见产品化项目
（软论据，不称首创）。

## 三、架构

| 层 | 目录 | 职责 | 硬约束 |
|---|---|---|---|
| L0 口径 | `data/ruleset.v1.json` | 阈值 / 白名单 / 版本号 | 不含逻辑；是 `data/README.md` §4 的机器镜像 |
| L1 核心 | `src/core/**` | 解码 / 解析 / 规则 / 报告 / 修复 | **纯函数**：不碰 DOM、不发网络、不读时钟、不读 locale、不用随机 |
| L2 编排 | `src/core/pipeline.js` | 把 L1 串成一次体检 | 不做判定、不渲染 |
| L3 界面 | `src/ui/**` | 拖放 / 渲染 / 导出 | 只消费 `core/pipeline`；不实现规则、不写阈值 |
| L4 构建 | `tools/**` | 内联构建 / 门禁 / 数据生成 | 不进产物 |

模块系统是自写的 `SP.define` 注册表（经典脚本，不是 ESM），
因此**浏览器与 Node 测试走同一条执行路径**，构建只需按序拼接。

### 3.1 单文件构建

`tools/bundle.mjs` 按**显式清单** `SOURCE_FILES` 顺序拼接源码，并把
`data/ruleset.v1.json` 注入为 `SP.define("data/ruleset", …)`。
清单与 `src/**/*.js` 实际集合必须**逐项相等**（多一个、少一个都报错），
从机制上杜绝"新增文件没进产物"。

构建产物自检：无 `<script src>` / `<link>` / `@import` / 远程 `url()` /
`fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` / `http(s)` 字面量 / 本机绝对路径。

### 3.2 数据契约

- **cue 模型**（L1 唯一中间表示）：`index / startMs / endMs / textLines / textLineNumbers /
  format / sourceLine / endLine / timeLine`。
- **finding 严格 7 键**：`ruleId / severity / line / field / expected / actual / message`。
  语言档位（zh/en/ja）写进 `expected` 与 `message` 文案，**不新增键**（避免下游 schema 漂移）。
- **行号口径**：`timing.*` 取 `timeLine`（时间码所在行）；`readability.*` / `hygiene.*`
  取 `sourceLine`（cue 块起始行）。
- **报告键序固定**：`schemaVersion → rulesetVersion → inputSha256 → summary → findings →
  fixes → skipped → capabilities → diagnostics`；`findings` 按 `(line, ruleId)` 排序；
  无时间戳、无随机 ID、无本机路径。

## 四、四类规则

### 4.1 时序 `timing.*`（12 条）

重叠 / 零时长 / 负时长 / 间隔过小 / 起点倒退 / 重复 cue / 负起点 / 越过媒体时长 /
时间码不可解析 / 文件顺序≠时间顺序 / 时间码精度 / fps 漂移。

**T11 fps 漂移拟合**是本题技术含量最高的一条：

- 参考轴是**按声明帧率重建的帧栅格**：`ref₁ = 0`，
  `refᵢ = refᵢ₋₁ + round(Δobservedᵢ ÷ (scale × 1000 ÷ declaredFps)) × (1000 ÷ declaredFps)`。
- 在 `offset × scale` 二维网格上粗搜（`drift.offsetStepCoarse` / `drift.scaleStepCoarse`）
  再局部细化（`drift.offsetStepFine` / `drift.scaleStepFine`），并列最优按
  `drift.tieBreak`（先 offset 小、再 scale 小）确定性取舍。
- **判据是"残余漂移"**：`|scale − 1| × 时间跨度 > drift.residualMaxMs`。
  为什么不用"拟合残差中位数超限"——**自由 `scale` 会把纯比例漂移完全吸收**，
  对任意等比拉伸总能选到某个 `scale` 使残差 < 1ms，那条判据**永不产出 finding**
  （原型 14 组变体逐一验证过）。残差中位数是**拟合目标**，不是判据。
- 另有 `drift.gridToleranceMs` 作护栏：只有文件确实落在声明帧栅格上才判漂移，
  不落格 → `skipped(not_frame_grid)`；样本不足 `drift.minSamples` → `skipped`；
  未声明帧率 → `skipped(media_fps_unknown)`。**绝不猜。**

### 4.2 可读性 `readability.*`（7 条）

CPS / 行长 / 行数 / 字符下限 / 时长下限 / 时长上限 / 相邻重复文本。

- 可见字符一律**定点千分字符**（milli）：全角 = 1000，半角 = 500；
  空白、换行、ASS 覆写块 `{...}`、HTML 标签 `<...>`、SDH 标记不计入。
- 行长上限的单位是"该档字符数"，折成千分字符：中/日 = `line.maxWidthFull × 1000`，
  英 = `line.maxWidthHalf × 500`。
- 语言档由 cue 的**主导文字类别**判定（全角为主 → zh；假名过半 → ja；半角为主 → en），
  逐码点判定，**不调用分词或模型**。
- 判定全部走**定点整数比较**（`chars_milli / duration_ms` 折成整数比较），不用浮点直接比。

### 4.3 卫生 `hygiene.*`（10 条）

CJK–拉丁间距 / 标点宽度 / 行尾句号 / 未闭合标签 / ASS 覆写块残留 / 占位符残留 /
`<font>` 残留 / SDH 标记 / 全大写 / 连续重复标点。

- 每条都配"已知不报"**白名单**（`hygiene.whitelist`：`iPhone` / `iPad` / `macOS` /
  `iOS` / `e.g.` / `i.e.` / `etc.` / `♪`），**命中次数进报告**（`summary.whitelist`），
  不得静默。
- 同一条 cue 的多行命中同一条规则时只报一条（`line` 相同 → 重复项只是噪声），
  报告因此保持确定性、可读。
- 精度优先：S06 只豁免**单字母**数学表达式 `{x}`，多字母命名占位符 `{name}` 照报；
  S08 的歌词语境白名单只对"整条以 `♪` 起止"生效。

### 4.4 修复（白名单 + 单调性）

**只做可逆无损动作**：去重叠 / 修间隔 / 序号重编 / 去行尾空白 / 闭合标签 / 统一换行。
**禁止**：改文本、改断句、重排语序、合并或拆分 cue、改字号颜色、删 cue。

- 修复落在**原文行**上（行号 → 新行内容），所以修复后的文件与原文逐行同构，
  格式不需要重新序列化，也就不会引入格式漂移。
- 时间码重写**保留原行的分隔符与小数位数**（`HH:MM:SS,mmm` / `HH:MM:SS.mmm` /
  `H:MM:SS.cc` 各自同形重写）；找不到两个时间码 token 时返回 `null`——**宁可不修，也不猜格式**。
- 缩短时间码时以 `duration.min` 作护栏：若缩短后时长低于可读性下限，宁可不修，
  否则会立刻制造一条新的 `readability.duration-short`。**每条规则的违规数不得因修复而增加。**
- 序号重编有**保守前提**：全部是 SRT、块区间互不重叠、所有非空行都落在某个块内、
  每个块首行都是序号行。不满足就整条跳过（不凭空造序号）。
- 修复记录进 `fixes[]`（`ruleId / line / action / before / after`），报告可见；
  不可修时 `fixes[]` 为空。

## 五、质量保证：差分对照与门禁

### 5.1 差分对照（真值侧独立实现）

`tools/samples/*oracle.mjs` 按 `plan/03` 把判定式**重写一遍**，且**不 import `src/core/**`**。
因此"实现 vs 真值"是两套独立代码的对照，而不是"比对两份预先算好的答案"。
写错或改错立刻抛错。

真值只存**输入与期望**（`expectFindings` 只允许 `ruleId` / `line` / `field`），
**不得写 `observed` / `actual` / `message`**——观测由规则引擎运行时实算。

### 5.2 门禁

| 门 | 命令 | 判据 |
|---|---|---|
| 布局门 | `node tools/check-sprint-layout.mjs` | 计划套件 / 交接单 / **三处状态副本逐处一致** / 缺口列无已 ✅ 里程碑 / 测试清单逐项列出 |
| 口径门 | `node tools/check-ruleset.mjs` | §4 ↔ ruleset 双向键集相等 + 逐值相等 + `src/**` 无区分性阈值字面量 |
| 真值门 | `node tools/check-truth.mjs` | 样本 ↔ 真值一一对应 / 无观测字段 / 覆盖度按规则域列全 / 内容白名单 |
| 生成器 | `node tools/gen-samples.mjs --check` | 85 文件**逐字节一致** + 无孤儿 |
| 变异自检 | `node tools/selftest-layout.mjs` | 7 组真实数据变异，布局门必须**变红**（证明门不是恒真） |
| 产物 | `node tools/build.mjs --check` | 产物与源码同基线，逐字节 |
| 浏览器 e2e | `node tools/e2e-browser.mjs` | 从**产物文件**用 headless Chrome 打开，走完整交互链 |

### 5.3 反例测试（证明门不是恒真）

- 布局门：7 组变异（删锚点 / 翻状态 / 写回缺口 / 删交接单 / 删装订行 / 测试清单漏项 /
  删状态表）各自必须被检出。
- 真值门：写 `observed` 字段 / 删真值 / 篡改字节 / 造孤儿 / 从 README 删规则 /
  把 cue 数改小 → 门必红。
- 生成器：篡改一个样本字节 / 多出一个孤儿样本 → `--check` 必红。
- 卫生：篡改后 precision 必然下降 → 测试断言 `precision === 1`。
- 修复：不可修样本断言 `after === before` 且 `fixes[]` 为空（**不是**"没样本所以没得修"）。

## 六、非目标（写死，不再论证）

| 非目标 | 理由 |
|---|---|
| 自动断句重排 | 断句依赖语义与语感，自动重排必然改文本语义；与"只做可逆无损修复"的红线直接冲突。 |
| 音频强制对齐 | 需音频解码 + 声学模型（WASM + 权重），突破"单文件、断网、零依赖"预算；且结果不确定，无法给出确定性真值。 |
| 平台规则库 | 各平台隐式审核规则不公开、易过期、无法查证；内置等于把不可核验的传闻写成硬判定。 |
| CLI / 桌面 exe / 本地服务 | 形态收敛为单文件 HTML：CLI 要装运行时、exe 要打包与信任二进制、本地服务要管端口。 |
| 多形态并行 | 避免"CLI 真做、界面空壳"的通行证。 |

### 7.2 端到端 0 容差

| 域 | 结果 | 证据 |
|---|---|---|
| 三格式解析（cue 边界 / 行号映射 / 诊断码） | 24 份样本 **0 容差** | `tests/samples_generator.test.mjs` |

### 7.3 修复单调性

| 样本 | 结果 |
|---|---|
| 可修样本（重叠 + 间隔 + 未闭合标签 + 行尾空白 + 序号跳号） | 总违规数 `after < before`，**每条规则都不增加**；每条 `fixes[]` 记录的规则确实被修掉 |
| 不可修样本（占位符 / ASS 覆写块 / SDH / 全大写） | `after === before` 且 `fixes[]` 为空 |
| 文本保全 | 归一化掉白名单内的两处改动（行尾空白、补闭合标签）后，逐条文本**逐字节相等** |

### 7.4 报告三格式同源

JSON / Markdown / CSV 共用**同一份 findings 数组**（单一渲染源）。
测试断言"条目数相同 + 每条的 `ruleId`/`line` 一致"，且 CSV 按 **RFC 4180** 转义
（含逗号 / 引号 / 换行的字段加双引号、内部引号翻倍），用测试侧独立实现的 CSV 解析器**反向验证**。

### 7.5 性能（10MB / 5000 cue）

```bash
node tools/gen-samples.mjs --perf   # → out/perf-10mb-5000cues.srt（不入仓）
node tools/bench.mjs --runs 5       # 另含 1 轮预热，不计入统计
```

| 项 | 实测值 |
|---|---|
| 样本 | 10 558 893 bytes（10.07 MB）/ 5000 cue |

| 产出 | findings 15000 / json 4 285 346 B / md 2 154 602 B / csv 2 124 173 B |

> `tools/bench.mjs` 只测量并打印，不做"必须达标"的断言——是否达标由人判断。

`tools/bench.mjs` 本身也有契约测试（`tests/bench_contract.test.mjs`）：

## 八、已知限制（不得写成已达成）

- **CI 未跑过**：本仓库尚未建远端，`npm run verify` 是本地等价校验；浏览器 e2e 已在
  本机 headless Chrome 验过（**未接远端，CI 待首推验证**）。
- **性能是单机单次实测**：不是跨机器承诺，也不是"任意 10MB 字幕都能 1.2s"的承诺。
- **修复白名单是有边界的**：文本层面的缺陷（占位符、ASS 覆写块残留、全大写、SDH 标记、
  交叉嵌套标签、标点宽度、行尾句号、CJK 间距）**不可修**——修它们必然改文本，
  违反"只做可逆无损修复"的红线。这些 finding 会如实报出，但 `fixes[]` 为空。
- **GBK 解码依赖宿主 ICU**：无完整 ICU 的 Node 构建下 `TextDecoder('gbk')` 抛错，
  `gen-samples` 会显式报错而不是静默降级（浏览器侧始终可用）。
- **本工具是投放前的辅助检查**，不构成对字幕质量或平台审核结果的保证。
