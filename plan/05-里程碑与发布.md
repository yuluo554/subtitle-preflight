## 三、发布流程

1. **定版**：产物内版本号、README、tag 名、Release 名四处一致；定版后立刻复跑全量测试。
2. **构建**：`node tools/build.mjs` → `--check` → 双跑 `cmp` 逐字节一致。
3. **附件**：`dist/subtitle-preflight.html`（构建产物本身）+ 确定性源码包
   （`git archive --format=tar --prefix=subtitle-preflight-0.1.0/ v0.1.0 | gzip -9n`，从 **tag** 构建）。
4. **tag**：annotated；本地 `git rev-parse v0.1.0` 必须等于远端 `git/ref/tags/v0.1.0` 的 `object.sha`。
5. **Release**：正文写 sha256（不写进包内文档）；`isDraft=false` 且附件 `state=uploaded`。
6. **留档**：`plan/RELEASE-M6.md` 两栏 + 覆盖对账；tag 之后只允许文档面提交
   （`git diff --name-only v0.1.0..HEAD` 只含 `plan/`、`README.md`）。

## 五、风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| GBK 解码依赖宿主 ICU | 无 ICU 的 Node 构建下 `TextDecoder('gbk')` 抛错 | 解码层捕获并以 `lossy` 降级 + 诊断；浏览器侧始终可用 |
| 单文件构建漏收新文件 | 产物缺模块，运行时 `unknown module` | 构建门断言 `SOURCE_FILES` == `src/**/*.js` 实际集合 |
| 阈值双份漂移 | 报告口径与文档不一致 | `check-ruleset` 双向对账 + 区分性字面量扫描 |
| 规则误报损害可信度 | 用户不再信任报告 | 卫生规则 precision 100% 硬门 + 白名单计数 |
| 报告不确定性 | 无法作为 CI 门禁 | 无时间戳/随机 ID/绝对路径 + 双跑逐字节断言 |
| 浏览器 `file://` 限制 | 拖放或下载被拦 | 保留粘贴框作为备用输入；导出用 `Blob` 下载 |
| 未实现能力被读成"通过" | 虚假安全感 | `capabilities` + `skipped[]` 进产物；界面折叠区显式展示 |
