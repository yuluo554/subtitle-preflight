## 二、真值结构

`data/truth/<域>/<sample>.json`（与样本同名同结构；标注准则见 `data/truth/README.md`）：

**解析域（`format/`）——真正的标注实现是 `tools/samples/annotate`（独立于 src/core）**：

```json
{
  "sample": "format/srt-v3-missing-index.srt",
  "format": "srt",
  "variant": "missing-index",
  "encoding": "utf-8",
  "bom": null,
  "eol": "lf",
  "cueCount": 4,
  "cues": [
    { "index": 1, "declaredIndex": null, "startMs": 1000, "endMs": 3000,
      "textLines": ["角色甲：夜航开始了。"], "sourceLine": 1, "timeLine": 2,
      "endLine": 3, "textLineNumbers": [3] }
  ],
  "diagnostics": [ { "code": "decode.gbk-fallback" } ]
}
```

**规则域（`timing/` / `readability/` / `hygiene/`）**：

```json
{
  "sample": "timing/t01-overlap.srt",
  "class": "T01",
  "primaryRuleId": "timing.overlap",
  "expectFindings": [ { "ruleId": "timing.overlap", "line": 6, "field": "startMs" } ],
  "planted": [ { "id": "t01-overlap", "cls": "T01", "ruleId": "timing.overlap", "diffNonEmpty": true } ]
}
```

- `expectFindings` 的每一项**只允许** `ruleId` / `line` / `field` 三个键。
- `expectNoFindings` 用于显式声明"看起来像但不报"的近似形态（带 `why`）。
- 可读性/卫生的 cue 级真值额外给出 `timeLine` 与度量（`charsMilli` / `durationMs` / 可见行数），
  但那是**输入侧可复算的标注值**，不是被测实现的观测输出。

## 三、真值纪律

1. **真值只存输入与期望**：`expectFindings` 只写 `ruleId` + `line`（必要时加 `field`），
   **不得写 `observed` / `actual` / `message`**——观测由规则引擎运行时实算，
   否则基准退化成"比对两份预先算好的答案"。`tools/check-truth.mjs` 深扫全部真值文件。
2. **期望值可由输入独立复算**：每条 `expectFindings` 必须能从样本原文 + `data/README.md` §4 手算出来；
   标注脚本不调用被测实现（`tools/samples/*oracle.mjs` 不 import `src/core/**`）。
3. **样本与真值同提交**：任何样本改动必须同步改真值；`tools/gen-samples.mjs --check` 断言
   "重生成结果逐字节一致"，`tools/check-truth.mjs` 断言"样本 ↔ 真值一一对应、无孤儿"。
4. **生成器可复现**：固定种子（本轮生成器不使用随机）；输出 LF；文件按 Unicode 码点序写出；`--check` 位级比较。
5. **内容白名单**：只用 `示例剧` / `Sample Show` / `角色甲` / `Character A` 一类虚构名；
   不复制任何真实字幕、剧本、台词。生成器内置禁用词表，命中即抛错。
6. **真值覆盖度按规则域逐项列全**：任一规则无正例即视为覆盖不足，不得进入下一里程碑；
   覆盖度矩阵落在 `data/truth/coverage.json`，由 `tools/check-truth.mjs` 双向对账。
7. **植入器自证**：生成器每植入一处缺陷，断言"该位置在干净基线里确实没有这个缺陷"
   （即 diff 非空），否则该样本不得计入检出率分母。
8. **字节即口径**：`data/samples/**` 含 CRLF / UTF-8 BOM / GBK 变体，`.gitattributes` 已声明 `-text`，
   禁止 git 做行尾或编码归一（否则 `--check` 在干净 clone 上必红）。

## 四、数值口径

**唯一定义处是 `data/README.md` §4。** 本文不重复数值。机器可读镜像为
`data/ruleset.v1.json`，由 `tools/check-ruleset.mjs` 双向校验：

- §4 表格里的每个口径键都能在 ruleset 里找到同名键，值逐项相等；
- ruleset 里的每个键都在 §4 表格里出现过（防"代码里藏了第二份口径"）；
- `ruleset_version` 与 §4.7 的 `report.rulesetVersion` 一致。

修改任一数值的动作固定为：改 §4 → 改 ruleset → 同提交 → 跑 `check-ruleset`。
