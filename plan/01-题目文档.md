# 题目文档：字幕投放前体检（subtitle-preflight）

> **项目性质**：不参赛项目题（发布 GitHub **公开**仓库，署名 yuluo554）
> **目标产出**：`10-19-subtitle-preflight`（字幕投放前体检：单文件 HTML 本地 Web 应用）
> **版本史**：v1（2026-10-17 定稿）；依据查证基准日 **2026-10-17**，GitHub 检索实测窗口 **2026-10-18 10:33–10:45 UTC**（跨日不足 1 天，`data/README.md` 已如实标注）。
> **交付形态（唯一）**：**单文件 HTML 本地 Web 应用**——零安装、零后端、零 CDN、断网可用，双击打开即用。不提供 CLI、不提供桌面 exe、不提供本地服务端口。
>
> **定位宣言**：把 `.srt/.vtt/.ass` 拖进一个 HTML 文件，浏览器内解析，按「**时序 / 阅读速度 / 行长 / 排版卫生**」四类确定性规则体检，输出**带源文件行号定位**的 JSON / Markdown 报告 + 只做**可逆修复**的字幕文件。零安装、零上传、断网可用——现有字幕工具要么是 C# 桌面巨兽（SubtitleEdit 14603★），要么是 0–3 星一次性脚本。
>
> **品牌隔离**：本文档不提名本系列任何其他项目，不复制其他项目代码与文档，不与任何其他项目共享判定口径。

## 1. 介绍

### 1.1 痛点：字幕"能播"不等于"能投"

字幕出问题，几乎从不报错——它只是"看起来不太对"。以下原话均来自真实讨论（✅ 已核对，链接可直连）：

| 场景 | 原话（节选） | 出处 |
|---|---|---|
| 时间轴整体偏移 | "this only works with offsets and doesn't adjust the subtitle's playback speed… usually caused by playing a subtitle written for a given FPS played back on a different FPS" | HN **583 分**，`https://news.ycombinator.com/item?id=19248723` |
| 同一文件换平台就废 | "The whole subtitling world is very, very messy… You might have a file that works in one place, but when you upload it somewhere else, it doesn't work."；"Wish it supported ASS file formatting better though." | HN `https://news.ycombinator.com/item?id=30219276` |
| 质量长期被忽视 | "not enough people complain about the quality" | HN `https://news.ycombinator.com/item?id=41501570` |
| 断句/节奏不佳 | "细看下来其实译文的意思也没有错…可能只是因为**字幕断句断的不好**" | V2EX `https://www.v2ex.com/t/1209859` |
| 工具导出的时间线不理想 | "用剪映生成的带时间线的 srt 字幕文件**不够理想**"（同帖在求"智能断句哪家强"） | V2EX `https://www.v2ex.com/t/1029923` |
| 格式支持残缺 | "衣柜的字幕质量超赞只可惜跟我的版本不符…subsync **只能改 srt**，ass 的就无能为力了" | V2EX `https://www.v2ex.com/t/282431` |
| 时间轴校正靠手搓 | "追剧字幕时间轴不同步，造了个自动校正时间轴的轮子" | V2EX `https://www.v2ex.com/t/857400` |
| 时间轴直接不可用 | "时间轴**很混乱**，没法正常用" | V2EX `https://www.v2ex.com/t/1232325` |

把这些原话放在一起，痛点的形状很清楚：**问题出在"投放前"这一小时，而不是"翻译"或"压制"环节**。文件已经翻好了、时间轴也做过了，但没人告诉你它在另一个平台上会不会被截断、会不会快 2 秒、会不会一行塞 30 个字。

### 1.3 与既有工具的形态差异（✅ 可核验的形态事实）

| 维度 | SubtitleEdit（14603★） | 一次性脚本（0–3★） | 本题 |
|---|---|---|---|
| 安装 | Windows 桌面程序，需安装/解压 | 需 Python/Node 环境 | **双击一个 HTML 文件** |
| 平台 | 以 Windows 为主 | 看作者心情 | 任意有浏览器的系统 |
| 数据去向 | 本地（但需信任二进制） | 本地 | **文件不离开浏览器，零上传** |
| 规则可读性 | 图形化选项，规则不可导出 | 硬编码 | 规则阈值集中在可读的 ruleset，报告带 `ruleset_version` |
| 中文阈值 | 有 CPS 设置，但不是投放前体检的默认口径 | 通常无 | 中文/英文/日文分档，边界值有单测 |
| ASS 支持 | 完整 | 大多只做 SRT | **ASS 只取 Dialogue，跳过 Comment** |

形态差异不是"功能更多"，而是**把体检这件事的成本压到接近零**：不需要装、不需要开终端、不需要上传给任何在线服务。

### 1.4 方法论与 AI 时代独特性拷问

为什么必须是工具，而不是让 LLM 读一遍字幕？

- **① 持久/可复现的判定**：同一份文件、同一版 ruleset，任何时候跑出的 `findings[]` 必须逐字节一致。聊天式检查每次措辞不同、漏检不可复现，无法作为投放前的门禁。
- **② 进入既有工作流的交付物**：JSON 报告可进 CI/工单，Markdown 可贴群，修复后的字幕文件可直接替换上传。聊天窗口里没有"文件"。
- **③ 可核验的真值**：缺陷是**确定性的**——重叠就是 `next.start < cur.end`，CPS 就是字数除以时长。这类问题不需要语义理解，需要的是**不漏、不噪、可定位到行**。
- **④ 隐私边界**：未公开的剧集字幕是版权资产。上传到任何在线服务都越界；浏览器内解析是唯一零信任成本的路径。

**本题不做的"聪明事"**：不自动断句重排、不翻译、不做音频强制对齐。这三件事都要改语义或需要模型，且无法给出确定性真值——详见 §6。

## 2. 任务要求

首期限定 **5 个模块**，逐个交付；扩展项见本节末。所有模块共享四条纪律：

- **纯前端纪律**：全部逻辑在浏览器内完成，`file://` 直接可用；**零网络请求**（无 CDN、无字体、无遥测、无 fetch/XHR 到外域），断网打开功能完整。
- **口径单一定义**：全部阈值（CPS 分档、行长、时长上下限、间隔、fps 拟合网格、`ruleset_version`）**只在 `data/README.md` §4 定义一次**；代码从 ruleset 读取，文档与报告只引用口径键，不写第二份数值表述。
- **确定性纪律**：同一输入 + 同一 ruleset → 同一输出。报告默认**不含生成时间、不含随机 ID、不含本机路径**；对象键序、数组排序、数值格式全部固定。修复只在内存中进行，原文件永不覆盖。
- **可定位纪律**：每条 finding 必须带 `line`（源文件 1-based 行号）与 `field`，能回到原文的那一行；行号映射表由模块 ① 产出，后续模块只消费。

### 模块 ①：输入与规范化（M1）

- **输入**：`.srt` / `.vtt` / `.ass`（`.ssa` 按 ASS 处理），支持单文件与一次拖入多个文件。
- **输出**：
  1. **统一 cue 模型**：`{index, startMs, endMs, textLines[], format, sourceLine, endLine}`；
  2. **原文行号映射表**：每个 cue 的起止行号（1-based），以及文本行到源文件行的逐行映射；
  3. 解析诊断：编码判定结果、换行归一结果、被跳过的结构块清单。
- **做法**：
  - **编码嗅探**：BOM 优先（UTF-8 BOM / UTF-16LE / UTF-16BE）→ 无 BOM 时按 UTF-8 严格解码 → 失败回退 GBK（`TextDecoder('gbk')`）。回退结果必须在界面与报告中显式标注，不允许静默。
  - **换行归一**：CRLF / CR / LF 统一为内部 LF；写回时按用户选择输出（默认与原文件一致）。
  - **SRT**：容忍序号缺失、跳号、序号与块数不一致；时间码 `,` 与 `.` 混用；空行噪声；块内多余空行。
  - **VTT**：解析 `WEBVTT` 头、`NOTE` / `STYLE` / `REGION` 块并与 cue 分离（保留但不参与体检）；cue 标识行可有可无；时间码支持 `MM:SS.mmm` 与 `HH:MM:SS.mmm`。
  - **ASS**：只取 `[Events]` 段的 `Dialogue:`，**跳过 `Comment:`**；按 `Format:` 行解析字段顺序（不假设固定列位）；时间码 `H:MM:SS.cc`（厘秒）转毫秒。
- **确定性纪律**：解析器不依赖浏览器 locale 与时区；多文件按**文件名 Unicode 码点序**处理；同一文件重复解析结果逐字节一致。
- **验收**：
  - **24 份样本（3 格式 × 8 变体）**：cue 数与每条起止时间与人工标注**完全一致**（0 容差）；
  - GBK 样本无乱码（中文文本逐字比对一致）；
  - 行号映射误差 **0**（每个 cue 的 `sourceLine` 与标注一致）；
  - 8 类变体覆盖：BOM / CRLF / 序号缺失 / 序号跳号 / `,` 与 `.` 混用 / GBK 编码 / 行尾空白 / 空行噪声（VTT、ASS 各自替换为等价变体）。

### 模块 ②：时序体检（M2）

- **输入**：模块 ① 的 cue 模型 + 可选媒体时长（用户填写，缺省则跳过越界判定）。
- **输出**：`findings[]`，`ruleId` 前缀 `timing.`；fps 漂移另出 `timing.drift` 拟合结果 `{offsetMs, scale, residualMs, samples}`。
- **判定项（12 类，逐条固定 `ruleId`）**：

| 编号 | `ruleId` | 判定 |
|---|---|---|
| T01 | `timing.overlap` | `next.start < cur.end` |
| T02 | `timing.zero-duration` | `end == start` |
| T03 | `timing.negative-duration` | `end < start` |
| T04 | `timing.gap-too-small` | `0 <= next.start - cur.end < timing.gapMin` |
| T05 | `timing.non-monotonic` | 起点相对前一条倒退 |
| T06 | `timing.duplicate-cue` | 起止时间与文本完全相同 |
| T07 | `timing.negative-start` | 起点 < 0 |
| T08 | `timing.past-media-end` | 末 cue 结束超过声明时长（未填时长则跳过，并在报告标注 `skipped`） |
| T09 | `timing.unparsable-timecode` | 时间码无法解析，走回退路径 |
| T10 | `timing.file-order-mismatch` | 文件顺序 ≠ 时间顺序 |
| T11 | `timing.fps-drift` | 全局拟合残差超过口径阈值 |
| T12 | `timing.timecode-precision` | 亚毫秒、小时位溢出、毫秒位非 3 位 |

- **fps 漂移拟合**：对 `(原时间, 期望时间)` 做 **offset + scale 的网格搜索**（粗搜 → 局部细化，网格与阈值见口径 §4），输出最佳 `offsetMs` / `scale` 与残差；拟合只用通过 T01–T10 的"干净对"作样本，避免被坏 cue 带偏。拟合结果**只作诊断建议**，不自动应用。
- **确定性纪律**：网格搜索边界、步长、并列最优的取舍规则（取 `offset` 更小者，再取 `scale` 更小者）固定；同一输入两次运行的 `offsetMs` / `scale` / `residualMs` **完全一致**（不是"近似一致"）。
- **验收**：12 类缺陷的合成样本**检出率 100%、误报 0**；漂移样本的复原误差 **< 1 帧**（按样本声明的 fps 换算）；同输入双跑参数完全一致。

### 模块 ③：可读性体检（M3）

- **输入**：cue 模型 + 语言档（中/英/日，可按文件或按 cue 判定）。
- **输出**：`findings[]`，`ruleId` 前缀 `readability.`，每条带实测值与阈值。
- **判定项（7 类）**：

| 编号 | `ruleId` | 判定 |
|---|---|---|
| R01 | `readability.cps` | 每秒字符数超过该语言档上限（全角/半角按口径折算） |
| R02 | `readability.line-length` | 单行超过该语言档行长上限（全角字宽 / 半角字宽） |
| R03 | `readability.too-many-lines` | 显示行数 > 2 |
| R04 | `readability.too-few-chars` | 单条可见文本 < 2 字 |
| R05 | `readability.duration-short` | 显示时长 < `duration.min` |
| R06 | `readability.duration-long` | 显示时长 > `duration.max` |
| R07 | `readability.repeated-text` | 相邻 cue 文本完全相同（非重复 cue，是"同一句挂了两条"） |

- **计数口径**：全角字符计 1，半角计 0.5（用于行长与 CPS 折算）；标签、ASS 覆写块、SDH 标记**不计入**可见字符；空白与换行不计。口径只在 §4 定义。
- **确定性纪律**：语言档判定不调用任何分词或模型，只用字符类别（CJK 统一表意 / 假名 / 拉丁）；阈值从 ruleset 读取；浮点比较用定点整数（字符数 × 1000 / 毫秒），避免浮点误差导致的边界抖动。
- **验收**：**200 条人工标注 cue** 的 CPS 与行长判定**100% 一致**；每条规则的边界值（等于上限 / 上限 + 1 / 下限 / 下限 − 1）各有单测；语言档切换后结果按口径变化且报告标注实际档位。

### 模块 ④：排版与语言卫生（M4）

- **输入**：cue 模型（只读）。
- **输出**：`findings[]`，`ruleId` 前缀 `hygiene.`。
- **判定项（10 类）**：

| 编号 | `ruleId` | 判定 |
|---|---|---|
| S01 | `hygiene.cjk-latin-spacing` | 中英/中数混排缺空格（如 `4K画质`、`用Python写的`） |
| S02 | `hygiene.punctuation-width` | 全半角标点混用（中文句内出现半角逗号/句号，或英文句内出现全角标点） |
| S03 | `hygiene.trailing-punctuation` | 行尾残留句末标点（字幕行不应以 `。`/`.` 收尾） |
| S04 | `hygiene.unclosed-tag` | `<i>`/`<b>`/`<u>` 未闭合或交叉嵌套 |
| S05 | `hygiene.ass-override-residue` | 非 ASS 输出中出现 `{\an8}` 一类覆写块，或 `{` 未闭合 |
| S06 | `hygiene.placeholder-residue` | 残留 `%s`、`%1$s`、`{0}`、`{name}` 等占位符 |
| S07 | `hygiene.font-tag-residue` | 残留 `<font ...>` 内联样式 |
| S08 | `hygiene.sdh-marker` | 残留 SDH 标记 `[music]`、`（笑声）`、`♪` 等 |
| S09 | `hygiene.all-caps` | 英文整句全大写（长度达到口径阈值才报） |
| S10 | `hygiene.repeated-punctuation` | 连续省略号 / 感叹号 / 问号（`...`、`！！！`、`？？`） |

- **误报控制**：本题的硬指标是 **precision 100%（宁漏不噪）**——报出的每一条都必须是人能一眼确认的。为此每条规则都必须有"已知不报"白名单（如专有名词 `iPhone`、`e.g.`、装饰性 `♪` 的歌词语境），白名单登记在 ruleset 并在报告中显示命中次数。
- **确定性纪律**：规则按 `ruleId` 固定顺序执行；同一 cue 的多条 finding 按（行号, `ruleId`）排序；正则不得依赖 `locale`。
- **验收**：**golden set 30 条**（人工逐条标注应报/不应报）上 **precision 100%、recall ≥ 90%**；每条规则至少 1 条正例与 1 条反例。

### 模块 ⑤：报告与安全修复（M5）

- **输入**：模块 ②③④ 的 `findings[]` + 原文件 + 行号映射。
- **输出**：
  1. **JSON 报告**：`{schemaVersion, rulesetVersion, inputSha256, summary, findings[], fixes[], skipped[]}`；每条 finding 为 `{ruleId, severity, line, field, expected, actual, message}`；
  2. **Markdown 报告**：按严重度分组，每条附"源文件第 N 行 + 原文片段"；
  3. **CSV 报告**：列顺序固定，便于进表格；
  4. **修复后字幕文件**：只做**可逆无损修复**，并附 **diff**（逐行 before/after）。
- **允许的修复（白名单，超出即不修）**：

| 修复 | 说明 |
|---|---|
| 去重叠 | 仅缩短前一条 `end` 到后一条 `start`；不移动文本 |
| 修间隔 | 仅在 `0 <= gap < timing.gapMin` 且前一条可缩短时调整 |
| 序号重编 | 按时间序重排后连续编号 |
| 去行尾空白 | 只删行尾空格/制表符 |
| 闭合标签 | 只为未闭合的 `<i>`/`<b>`/`<u>` 补闭合，不新增样式 |
| 统一换行 | 按用户选择输出 CRLF/LF |

- **禁止的修复**：不改文本内容、不改断句、不重排语序、不合并/拆分 cue、不改字号/颜色、不删任何 cue。
- **确定性纪律**：报告默认**不含时间戳、不含随机 ID、不含本机绝对路径**；`inputSha256` 由原文件字节计算；两次导出必须**byte 级一致**。修复产物必须在报告中记录每条的 `before`/`after`，且原文件永不被覆盖（浏览器无法覆盖本地文件，这是形态自带的保险）。
- **验收**：
  - 报告两次运行 byte 级一致；
  - JSON 通过随包 schema 校验；
  - 修复后重跑模块 ②③ 的违规数**严格单调下降**（允许某条规则因修复位置移动而数量不变，但不允许上升）；
  - 10MB / 5000 cue 的全流程（解析 → 四类体检 → 报告 → 修复）在普通笔记本上**不超过 2s**（性能口径见 §4，不作硬性跨机器承诺）。

### 扩展项（不进首期硬承诺）

## 6. 边界与非目标

**不做（明确切割）**：

- **不做自动断句重排**——断句依赖语义与语感，自动重排会改文本语义，与"可逆无损修复"的红线冲突；
- **不做翻译/润色**——本题只判定"能不能投"，不判定"翻得好不好"；
- **不做音频强制对齐**——需要音频解码 + 声学模型（WASM + 模型权重），突破"单文件、断网、零依赖"的体积与离线预算；
- **不联网、不上传**——零网络请求是硬约束；不内置任何字幕库、片源、术语表（版权红线）；
- **不做云同步/账号体系**；
- **不覆盖原文件**——修复结果只能导出为新文件；
- **不做"字幕质量总分"**——单一分数会掩盖具体缺陷，报告只列可定位的条目；
- **不做平台规则库**——不内置任何平台的隐式审核规则（无法查证、易过期），阈值只作为可调的通用口径。

**首期范围限定**：仅 `.srt` / `.vtt` / `.ass`（`.ssa` 按 ASS）；仅中/英/日三档阈值；仅单文件与多文件拖入，不做目录递归；扩展项一律不进首期评分。

**诚实性要求（硬约束）**：

- 未实测的体积与性能不得写成已达成（见 §5 最后一行）；
- 检索数据为软论据，必须带检索式与基准日，不得写成"业界首创"；
- 报告中的 `skipped[]` 必须如实列出未执行的检查（如未填媒体时长导致的越界跳过）；
- 编码回退（GBK）必须在界面与报告中显式标注，不得静默；
- **品牌隔离**：不提名、不复制本系列任何其他项目；不与任何其他项目共享数据或口径。

**免责**：本工具是投放前的辅助检查，不构成对字幕质量或平台审核结果的保证；修复动作只做白名单内的可逆调整，是否采用由用户决定。
