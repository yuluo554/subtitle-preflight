# 03 · 模块详设

> 阈值一律引用 `data/README.md` §4 的口径键；本文不写第二份数值。
> 每条规则给出：输入 → 判定 → 输出（`ruleId` / `line` / `field` / `expected` / `actual`）→ 误报控制 → 验收。

## 一、模块 ① 输入与规范化（M1/M2）

### 1.1 解码

```
bytes → BOM 判定 → (UTF-8 BOM) strip + utf-8
                → (UTF-16LE/BE BOM) 对应解码
                → 无 BOM：utf-8 {fatal:true} → 成功即 utf-8
                          → 抛错 → gbk {fatal:false} → encoding="gbk", fallback=true
                          → 再失败 → utf-8 {fatal:false}, lossy=true
```

输出 `{text, encoding, bom, fallback, lossy}`。`fallback=true` 或 `lossy=true` 必须出现在
文件卡片徽章与报告 `diagnostics[]` 中。

### 1.2 换行归一

CRLF / CR → LF，记录 `originalEol ∈ {crlf, cr, lf, mixed}`；写回默认沿用原形态。
**归一前的行号与归一后的行号必须一致**（只替换行尾，不增删行）。

### 1.3 SRT

块结构：`[可选序号行] 时间行 文本行*`，空行分隔。

- 时间行正则：`^\s*(-?\d{1,4}):(\d{1,2}):(\d{1,2})[,.](\d{1,4})\s*-->\s*(-?\d{1,4}):(\d{1,2}):(\d{1,2})[,.](\d{1,4})(?:\s+.*)?$`
- 容忍：序号缺失、跳号、与块数不一致、`,`/`.` 混用、行尾空白、首尾与块间多余空行。
- 序号行判定：**下一行是时间行**且本行是纯数字，才吞掉该行为序号；否则该行是文本。
- 文本行数记入 `textLineNumbers`（1-based）。
- 时间码小数位 1–4 位按位数补零到毫秒（`.5` = 500ms，`.50` = 500ms，`.500` = 500ms），
  非 3 位或小时位 > 2 位时在 `diagnostics` 记 `parse.timecode-precision`（T12 的输入）。
- **序号缺失 / 跳号记诊断**（M2 修定）：`declaredIndex === null` → `parse.missing-index`（line = 时间行）；
  与块序不符 → `parse.index-mismatch`（line = 块首行）。事实同时记在 cue 的 `declaredIndex`。
  真值 `data/truth/format/srt-v3|v4-*.json` 的 `diagnostics` 即按此口径标注（`data/truth/README.md` §4
  明确把「解析诊断码」列为格式真值的契约项）。
- **负起点**：小时位允许前导 `-`（`-00:00:00,500` → `-500ms`），这是 T07 的唯一输入形态。
  **M2 已实现**：`data/samples/timing/t07-negative-start.srt` 端到端产出 `timing.negative-start`。
- **块内空行 = 块终止符**（M2 决定不容忍）：SRT 以空行分块，"块内多余空行"在本口径下等同于结束该块；
  空行后的孤儿内容若不成块头，显式报 `timing.unparsable-timecode`，**不得静默丢弃**。
  `v8` 样本只覆盖首尾与块间多余空行（见 `data/truth/README.md` §2.9）。

### 1.4 VTT（M2，已实现）

- 首行必须是 `WEBVTT`（允许其后有 header 文本），整行跳过。
- `NOTE` / `STYLE` / `REGION` 块整块跳过，产出 `parse.skipped-block`（带**块首行**行号），不静默丢弃。
- cue 标识行可有可无；时间行 `MM:SS.mmm` 与 `HH:MM:SS.mmm` 都接受，`-->` 后可带 settings。
- 行号映射：`sourceLine` = 标识行（无标识时 = 时间行）；`textLineNumbers` = 文本行逐行；`endLine` = 末文本行
  （无文本行时 = 时间行）。
- `-->` 行解析失败时与 SRT 同款回退：产出 `timing.unparsable-timecode` + `parse.unparsable-timecode`。

### 1.5 ASS（M2，已实现）

- 只取 `[Events]` 段；`Comment:` 行**跳过并计数**（`parse.skipped-comment`，带行号）。
- 读取 `Format:` 行的字段顺序，建立 `name → index` 映射；**不假设固定列位**（`ass-v3` 乱序）。
- `Text` 是最后一列，可含逗号：前 N−1 列按逗号切，其余全归 `Text`。
- 时间码 `H:MM:SS.cc`（厘秒）→ 毫秒；`Dialogue:` 文本按 `\N` 拆行。
- `sourceLine` = `Dialogue:` 行号；`textLineNumbers` = `[sourceLine]`（ASS 无独立文本行）；
  `\N` 拆出的多行共用同一行号。
- `Dialogue` 早于 `Format` 缺列映射时记 `parse.missing-format`；时间码坏掉记 `timing.unparsable-timecode`。

### 1.6 验收

| 项 | 判据 | 对应测试 |
|---|---|---|
| cue 数与起止时间 | 24 份样本（3 格式 × 8 变体）0 容差 | `tests/samples_generator.test.mjs`（M2 已扩至 24 份） |
| 行号映射 | `sourceLine`/`timeLine`/`endLine`/`textLineNumbers` 与标注一致 | `tests/parse_srt.test.mjs` + `tests/parse_vtt.test.mjs` + `tests/parse_ass.test.mjs` |
| 解析诊断码 | 与真值 `diagnostics`（剔除 `decode.*`）0 容差 | `tests/samples_generator.test.mjs` |
| GBK | 中文逐字一致 + `fallback=true` | `tests/decode.test.mjs` |
| 8 类变体 | BOM / CRLF / 序号缺失 / 跳号 / 逗号点号混用（VTT 短时间码、ASS 乱序列） / GBK / 行尾空白 / 空行噪声 | 三份解析器测试 + `tests/samples_generator.test.mjs` |
| 未实现解析器 | 无（三格式均 `implemented`）；未知格式仍返回 `parser.unsupported` 而非空成功 | `tests/parse_srt.test.mjs` |

## 二、模块 ② 时序体检（M3）

规则执行顺序固定为 T01 → T12，同一条 cue 的 finding 按 `(line, ruleId)` 排序。

| ruleId | 判定式 | line | field | 备注 |
|---|---|---|---|---|
| `timing.negative-start` | `startMs < 0` | timeLine | startMs | 先于其他判定 |
| `timing.negative-duration` | `endMs < startMs` | timeLine | endMs | |
| `timing.zero-duration` | `endMs === startMs` | timeLine | endMs | |
| `timing.unparsable-timecode` | 解析器回退路径产生 | timeLine | timecode | 由解析层产生，规则层透传 |
| `timing.overlap` | `next.startMs < cur.endMs` | next.timeLine | startMs | 对相邻对 |
| `timing.gap-too-small` | `0 <= gap < timing.gapMin` | next.timeLine | startMs | 重叠不重复报 gap |
| `timing.non-monotonic` | `startMs < prev.startMs` | timeLine | startMs | 文件顺序 ≠ 时间顺序 |
| `timing.file-order-mismatch` | 全序列起点非单调 | 首个倒退 cue 的 timeLine | startMs | 与 T05 合并输出一条 |
| `timing.duplicate-cue` | 起止与文本完全相同 | 后一条 timeLine | text | |
| `timing.past-media-end` | `max(endMs) > mediaDurationMs` | 末条 timeLine | endMs | 未填时长 → `skipped` |
| `timing.fps-drift` | 拟合残差 > `drift.residualMaxMs` | 1 | fit | 需 `samples >= drift.minSamples` |
| `timing.timecode-precision` | 亚毫秒 / 小时位 > 2 位 / 小数位 ≠ 3 | timeLine | timecode | 解析期记录，规则期输出 |

**fps 漂移拟合**：模型 `expected = offset + scale × actual`。
粗搜 offset ∈ `drift.offsetRange` 步长 `drift.offsetStepCoarse`，scale ∈ `drift.scaleRange` 步长 `drift.scaleStepCoarse`；
以残差中位数为目标，取最优格点后在其 ±1 步邻域按 `drift.offsetStepFine` / `drift.scaleStepFine` 细化。
并列最优按 `drift.tieBreak`。只用通过 T01–T10 的相邻对作样本。

**验收**：12 类合成样本检出率 100%、误报 0；漂移复原误差 < 1 帧；同输入双跑参数逐位一致。

## 三、模块 ③ 可读性（M4）

| ruleId | 判定式（定点） | 备注 |
|---|---|---|
| `readability.cps` | `charsMilli > cpsLimit × durationMs` | 全角计 1000，半角计 500；`cpsLimit` 由主导文字类别选档 |
| `readability.line-length` | 任一行 `widthMilli > 该档行长上限（milli）` | 中/日 = `line.maxWidthFull × 1000`；英 = `line.maxWidthHalf × 500` |
| `readability.too-many-lines` | `visibleLines.length > line.maxLines` | |
| `readability.too-few-chars` | `charsMilli < line.minChars × 1000` | |
| `readability.duration-short` | `durationMs < duration.min` | |
| `readability.duration-long` | `durationMs > duration.max` | |
| `readability.repeated-text` | 相邻 cue 文本完全相同且时间不同 | 与 T06 区分：T06 时间也相同；报在后一条 |

> **单位口径（M1 定稿）**：`line.maxWidthFull` / `line.maxWidthHalf` 的口径单位是"该档字符数"，
> 折成千分字符后才是 milli 上限（全角 1000 / 半角 500）。`data/truth/README.md` §2.5 同文，样本按此标注。

**可见字符计数**：先剥离 ASS 覆写块 `{...}`、HTML 标签 `<...>`、SDH 标记（口径白名单），
再去空白与换行。字符类别由码点区间判定（CJK 统一表意 / 假名 / 谚文 → 全角；ASCII → 半角；
全角标点区间 → 全角）。**不调用任何分词或模型。**

**验收**：200 条标注 100% 一致；每条规则四个边界值（上限、上限 + 1、下限、下限 − 1）各一条单测；
语言档切换后结果变化且报告标注档位。

## 四、模块 ④ 卫生（M5）

10 条规则按 `ruleId` 固定顺序执行。每条都配"已知不报"白名单（`data/ruleset.v1.json` 的
`hygiene.whitelist`），白名单命中次数进报告。

| ruleId | 判据 | 白名单示例 |
|---|---|---|
| `hygiene.cjk-latin-spacing` | CJK 与拉丁/数字直接相邻且两侧都不是标点 | `iPhone`、`4K`（作为整体词） |
| `hygiene.punctuation-width` | 中文语境出现 `, . ! ? : ;`，或英文语境出现全角标点 | `e.g.`、`3.14` |
| `hygiene.trailing-punctuation` | 行尾为 `。` / `.`（问号、感叹号不报） | 省略号、缩写 |
| `hygiene.unclosed-tag` | `<i>/<b>/<u>` 未闭合或交叉嵌套 | 自闭合形态 |
| `hygiene.ass-override-residue` | 非 ASS 输出含 `{\...}` 或 `{` 未闭合 | — |
| `hygiene.placeholder-residue` | `%s`、`%1$s`、`{0}`、`{name}` | 数学表达式 `{x}` |
| `hygiene.font-tag-residue` | 残留 `<font ...>` | — |
| `hygiene.sdh-marker` | `[music]`、`（笑声）`、`♪` | 歌词语境（整条以 ♪ 起止） |
| `hygiene.all-caps` | 全大写且长度 ≥ `hygiene.allCapsMinLength` | 专有名词、缩写 |
| `hygiene.repeated-punctuation` | 同类标点连续 ≥ `hygiene.repeatPunctMin` | — |

**验收**：30 条 golden set 上 precision 100%、recall ≥ 90%；每条规则至少 1 正例 + 1 反例。

> **行号与口径澄清（M1 定稿）**
> - 卫生属**文本类** finding，`line` 取 cue 的 `sourceLine`（plan/02 §3.1）。
> - `hygiene.whitelist`（ruleset）**不含** `...`，因此 `...` 计为连续同类标点（达到下限即报）；
>   S08 的歌词语境白名单只对"整条以 `♪` 起止"生效。
> - S06 只豁免**单字母**数学表达式（`{x}`）；多字母命名占位符（`{name}`）照报。

## 五、模块 ⑤ 报告与修复（M5）

### 5.1 报告

- JSON：键序固定（见 plan/02 §3.3），2 空格缩进，结尾换行。
- Markdown：按 severity 分组；每条含 `第 N 行` 与原文片段（截断 60 字符，超出加 `…`）。
- CSV：列固定为 `ruleId,severity,line,field,expected,actual,message`；含逗号/引号/换行的字段按 RFC 4180 转义。
- 三格式**共用同一份 findings 数组**（单一渲染源），测试断言"条目数相同 + 每条的 ruleId/line 一致"。

### 5.2 修复白名单

| 修复 | 动作 | 前置条件 |
|---|---|---|
| 去重叠 | 缩短前一条 `end` 到后一条 `start` | 缩短后时长仍 > 0 |
| 修间隔 | 缩短前一条 `end` 以补足 gap | `0 <= gap < gapMin` 且前一条可缩短 |
| 序号重编 | 按时间序重排后连续编号 | 仅 SRT |
| 去行尾空白 | 只删行尾空格/制表符 | 所有格式 |
| 闭合标签 | 补 `<i>/<b>/<u>` 闭合 | 不新增样式 |
| 统一换行 | 按用户选择输出 CRLF/LF | 默认沿用原文件 |

**禁止**：改文本、改断句、重排语序、合并/拆分 cue、改字号颜色、删 cue。

### 5.3 修复后单调性

修复后重跑规则：每条规则的违规数 `after <= before`，且总违规数 `after < before`（存在可修项时）。
测试用"可修样本"与"不可修样本"各一份，后者断言 `after === before` 且 `fixes[]` 为空。

## 六、界面（M5）

- 拖放区 + 粘贴框（`file://` 下也可用）。
- 文件卡片：文件名、格式、编码（含回退标注）、cue 数、诊断数。
- 结果区：按四类分组；每条 finding 显示 `第 N 行`、ruleId、实测值/阈值、原文片段。
- 导出：JSON / Markdown / CSV / 修复后字幕；导出走 `Blob` + `URL.createObjectURL`，用完 `revokeObjectURL`。
- "未执行检查"折叠区：渲染 `skipped[]` 与 `capabilities`。
- **界面零判定**：所有数值来自 `core/pipeline` 的返回。
